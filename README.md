## Навигация и удаление

На страницах есть явные кнопки «Назад» и «На главную». Во время создания они сохраняют черновик текущей вкладки; продолжить можно из списка карточек. Счётчик навыков крупный, закрепляется при прокрутке и показывает остаток, потраченные очки и перерасход.

Кнопка «Удалить персонажа» находится под карточкой в списке. Удалять может владелец или мастер. После вопроса-подтверждения карточка и её фото удаляются из Supabase, права доступа удаляются каскадно. Сохранённые локальные черновики этой карточки очищаются; открытые вкладки того же браузера получают уведомление. У других устройств очистка происходит при следующей проверке доступа к карточке. Постоянно отключённый браузер нельзя очистить удалённо. Экспортированные пользователем файлы остаются у пользователя.

Данные персонажей не записываются в GitHub: там только исходники и исходный шаблон. Дополнительная миграция: `delete-cards.sql` после `roles.sql`. Проверки удаления: `tests/delete.sql` (транзакция с откатом) и проверка очистки кэша в `tests/engine.test.cjs`.

## Обновление: роли и создание персонажа

- Стартовая страница: игрок / мастер. Роль мастера назначается администратором в закрытой таблице `nd_private.masters`, кнопка не выдаёт права.
- Игрок регистрируется по логину (3–32 латинских буквы/цифры, `_`, `-`) и паролю от 6 символов. `111111` допустим. Старые аккаунты входят по прежним email и паролю.
- Новому игроку доступен пустой список. Чужие карточки видны только после выдачи мастером доступа через «Поделиться» по логину. Есть редактирование и просмотр.
- Создание: необязательная личность и фото → характеристики 2/1/1/0 → навыки (4 + Нейропластичность очков, ранг 0–3). Навык называется «Скрытность».
- Новая карточка создаётся без денег, экипировки, имплантов и перков. Экономика и магазин пока не добавлены. Исходный персонаж сохранён.
- Фото уменьшается в браузере до 640px и хранится вместе с приватной карточкой. Черновик создания живёт в sessionStorage текущей вкладки.

## Развёртывание обновления

На действующем проекте применён `roles.sql`; на новой установке сначала выполнить `supabase.sql`, затем `roles.sql`. Добавить UUID своего подтверждённого пользователя в `nd_private.masters` через SQL Editor (никогда из браузера).

Edge Function `register-player`: исходник `functions/register-player/index.ts`; публикуется с `verify_jwt=false`, поскольку регистрация доступна до входа. Сервер создаёт только обычных игроков через Auth Admin, а служебный ключ получает исключительно из окружения Supabase. Синтетические адреса `login@players.new-detroit.invalid` не являются почтовыми ящиками. Не отключайте подтверждение для обычной email-регистрации. Восстановления пароля по почте у игроков нет; администратор может сбросить его в Auth Users.

Регистрация ограничена 30 попытками в час для всего небольшого проекта. При дальнейшем росте стоит заменить это персональными лимитами и защитой от ботов. Защищённая атомарная функция лимита вызывается только серверной ролью.

Проверки: `node --test tests/engine.test.cjs tests/cloud.test.cjs`; транзакционные SQL-тесты `tests/roles.sql` и `tests/access.sql` откатывают фикстуры. `tests/register-live.cjs` запускается только вручную и создаёт временный аккаунт; его UUID выводится для последующей очистки. Не добавлять этот тест в CI.

## Подключение Supabase

### Проект и база

1. В https://supabase.com/dashboard создать проект на плане Free.
2. Дождаться готовности базы.
3. В **SQL Editor → New query** вставить содержимое `supabase.sql` и выполнить. Скрипт предназначен для нового проекта и выполняется один раз, в транзакции. При ошибке не запускать отдельные строки наугад — сохранить текст ошибки для исправления.
4. В Table Editor должны появиться `characters` и `character_access`, обе с включённым RLS.
5. Не отключать RLS. Только владелец выдаёт доступ, редакторы меняют данные, читатели смотрят. Анонимный посетитель не получает строки карточек. Знание ссылки не заменяет разрешение.

### Публичная конфигурация сайта

В настройках проекта или диалоге Connect найти **Project URL** и **Publishable key** (`sb_publishable_…`). Также поддерживается старый публичный ключ `anon`.

В `dist/config.js`:

```js
window.ND_CONFIG = {
  url: 'https://PROJECT_REF.supabase.co',
  key: 'sb_publishable_ПУБЛИЧНЫЙ_КЛЮЧ'
};
```

Эти два значения предназначены для браузера. Не подставлять `service_role`, `sb_secret_…`, пароль базы или personal access token: такие значения обходят ограничения и не должны попадать в репозиторий.

### Аккаунты для небольшой игровой группы

Для старта без отдельного почтового сервиса можно создать пользователей вручную в **Authentication → Users → Add user / Create user**: email, отдельный пароль, подтверждение email администратором. Использовать только проверенные адреса реальных участников. Участники входят кнопкой «Подключение и доступ». Пароли передавать владельцам лично, не в репозитории и не в этом чате.

Открытая регистрация кнопкой «Создать аккаунт» предполагает подтверждение email. Встроенная тестовая почта Supabase отправляет письма только разрешённым адресам команды и имеет низкий лимит. Для самостоятельной регистрации игроков нужен собственный SMTP. Не отключать подтверждение email ради обхода этого ограничения: доступ здесь выдаётся по проверенному адресу.

В **Authentication → URL Configuration** установить **Site URL** в окончательный адрес GitHub Pages, включая `/new-detroit/`. Указать этот адрес среди разрешённых Redirect URLs. Возвращаться к этой настройке после публикации, когда известен точный URL.

В первой версии нет самостоятельного восстановления пароля в интерфейсе: восстановление аккаунтов пока выполняется администратором проекта. Не путать игровые аккаунты с административным доступом к Supabase: игрокам не нужны приглашения в команду организации.

## Публикация

1. Убедиться, что проект загружен в ветку `main` и `config.js` заполнен.
2. В репозитории открыть **Settings → Pages**.
3. В **Build and deployment → Source** выбрать **GitHub Actions**.
4. На вкладке **Actions** открыть `Publish character terminal`. Если запуск ещё не начался, выбрать **Run workflow → main**.
5. Дождаться зелёного статуса. Workflow проверяет расчёты и публикует только `dist/`.
6. Открыть **Settings → Pages → Visit site**. Обычно адрес имеет вид `https://ИМЯ.github.io/new-detroit/`; точный адрес показывает GitHub.
7. После каждого изменения `main` сайт обновляется этим же workflow. Пока workflow не завершился успешно, новую версию нельзя считать опубликованной.

## Как пользоваться общей карточкой

1. Мастер входит в сайт своим игровым аккаунтом.
2. Заполняет персонажа или импортирует JSON.
3. Открывает «Мои карточки» → «Создать облачную копию текущей».
4. Нажимает «Поделиться», вводит email игрока, выбирает «Редактирование», выдаёт доступ.
5. Копирует ссылку и отправляет её игроку самостоятельно.
6. Игрок входит под разрешённым email. Мастер открывает эту же карточку. Изменения сохраняются автоматически, второй браузер проверяет свежие данные примерно раз в 10 секунд, когда поля не редактируются.

Мастер, создавший карточку, остаётся владельцем. Можно сделать наоборот: игрок создаёт карточку и выдаёт мастеру редактирование. Никакой скрытой роли мастера, автоматически читающей все аккаунты, в сайте нет.

При одновременном редактировании устаревшее сохранение отклоняется по номеру версии. Локальная копия сохраняется для восстановления; перед загрузкой актуальной версии нужно экспортировать свои изменения. Автоматического объединения конфликтующих правок пока нет.

## Что перенесено из таблицы

- Четыре характеристики с диапазоном 0–2 и 12 навыков с диапазоном 0–3.
- Два оружия, одна броня, шесть расходников, девять имплантов, пять программ и пять перков.
- Справочник: 14 видов оружия, 3 брони, 18 имплантов, 7 программ, 11 перков, 18 расходников. Пустые пункты исходных диапазонов не добавляются как предметы.
- Все описания предметов, характеристики, качество имплантов, количество расходников, баланс ED, инвентарь, локации, NPC и заметки.
- Максимум здоровья `3 + Тело`, броня по экипировке, свободный хром `3 + 2 × Тело − слоты`, киберпсихоз при превышении и очки навыков `4 + Нейропластичность − сумма рангов`.
- Изображение из исходного файла. Поля имени и биографии в исходнике были пустыми; они не заполнены вымышленными данными.

В исходнике свободные очки равны −1 — это сохранено и выделено. В броне число доступных ячеек теперь ограничено выбранным предметом, тогда как исходные флажки могли противоречить его значению. Текстовые условные бонусы предметов не применяются автоматически: таблица их тоже не рассчитывает. Формулы Google Sheets FILTER преобразованы в данные справочника, а VLOOKUP — в подбор предметов.

## Рекомендации по развитию

1. Во время игры держать здоровье, броню, оружие и перки ближе всего. Редкие настройки оставить в отдельных разделах.
2. Не переносить широкую сетку Excel буквально на телефон. Сохранить поля и механику, использовать вертикальные блоки и раскрывающиеся описания.
3. Согласовать термины «Тень» и «Скрытность», а также спорные границы дальности дробовика. До согласования не менять правила автоматически.
4. Отдельно решить учёт жетонов Драйва, ручного киберпсихоза и опыта: их текстовые упоминания уже есть, отдельных полей в исходной карточке нет.
5. Добавить журнал изменений и резервные копии перед расширением группы. Пока доступен ручной JSON-экспорт.
6. Следующим визуальным улучшением сделать смену портрета; сейчас используется исходный общий портрет.

## Локальный запуск и проверки

Открыть `dist/index.html` в обычном браузере для автономного просмотра. Для полноценного предпросмотра рекомендуется HTTP-сервер из папки проекта: `python -m http.server 4174 --bind 127.0.0.1 --directory dist`, затем http://127.0.0.1:4174/. Python не требуется опубликованному сайту. Шрифты загружаются из Google Fonts; без интернета используются системные.

Проверки: `node tests/engine.test.cjs`. Они покрывают расчёты из исходника, изменение характеристик, перегрузку хрома, повреждение брони, валидацию импорта и целостность справочника. Проверка реальной многопользовательской синхронизации и политик RLS требует подключённого Supabase и минимум двух аккаунтов.
